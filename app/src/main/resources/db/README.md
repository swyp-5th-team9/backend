# 데이터베이스 변경 관리

## 기본 원칙

- 운영 환경에 한 번이라도 적용된 Flyway 마이그레이션은 수정·이동·삭제하지 않는다.
- 테이블, 컬럼, 제약조건, 인덱스 변경은 `migration` 디렉터리에 버전 마이그레이션으로 추가한다.
- 애플리케이션 동작에 반드시 필요한 기준 데이터만 버전 마이그레이션에 포함한다.
- 로컬 개발과 테스트만을 위한 샘플 데이터는 운영 마이그레이션에 포함하지 않는다.
- 실제 매장처럼 지속적으로 변경되는 운영 데이터는 장기적으로 관리자 기능이나 별도 Import 작업으로 관리한다.

## 디렉터리 역할

```text
db/
├── migration/   # 모든 환경에 적용되는 스키마 변경과 필수 기준 데이터
└── local-seed/  # 로컬 개발 전용 샘플 데이터
```

`local-seed`는 로컬 프로파일에서만 읽도록 구성하고, 운영 및 마이그레이션 검증 테스트에서는 제외한다.

## 기존 마이그레이션

기존 V2, V4, V5, V10, V13에는 시드 데이터가 포함되어 있다. 이미 환경별 Flyway 이력과 체크섬이 생성되었으므로 해당 파일은 분리하거나 수정하지 않는다.

새로운 변경부터 다음 기준을 적용한다.

- 스키마 변경: `V{버전}__{설명}.sql`
- 필수 기준 데이터 변경: 스키마와 분리된 `V{버전}__{설명}.sql`
- 로컬 샘플 데이터: `local-seed` 아래의 반복 실행 가능한 SQL

로컬 샘플 SQL은 다시 실행되어도 중복이나 오류가 발생하지 않도록 `INSERT ... ON CONFLICT DO NOTHING` 등으로 멱등성을 보장한다.
